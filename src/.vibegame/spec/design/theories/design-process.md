# Design Process and Methods

Design methodology: how to generate ideas, organize knowledge, and allocate resources.

---

## 1. Brainstorming Methods

### Method Selection Guide

| Design Phase | Applicable Method | Output Characteristics |
|-------------|-------------------|----------------------|
| Early concept generation | Free thinking | Divergent, associative, unstructured |
| Mid system design | Structured thinking | Ordered, hierarchical, logical |
| Action/control design | Bodystorming | Concrete, demonstrable, interactive |

### Free Thinking

Start from a core word/idea, add related words and connect them, letting ideas extend outward to form a spider web-like map.

Principles: No judgment, no criticism, pursue quantity over quality, allow extension in any direction.

### Structured Thinking

**Flowcharts**: Continuously stack related ideas from the core starting point, avoid excessive deviation and branching, build ordered linear or branching structures.

**Tree Diagrams**: Determine the trunk (core concept), create main branches (primary categories), continue subdividing. Used to organize hierarchical development processes.

### Bodystorming

Step away from pen and paper, use your body to act out ideas. Physically simulate character actions and interactions, observe the fluidity and constraints of natural movements. Suitable for action games, VR/AR interaction design, gesture controls.

### Combined Usage

Early: free thinking to diverge ideas → Mid: structured thinking to organize systems → Refinement: bodystorming to test interactions.

## 2. Design Knowledge Structure

The full book is organized around 4 themes:
- **Innovation**: Game mechanics and player experience design
- **Creation**: Creative methods and development process
- **Balance**: Balance tuning and optimization
- **Problem Solving**: Interface design and problem-solving mechanisms

### Usage Methods

| Scenario | Method |
|----------|--------|
| Seeking random inspiration | Open to a random page, think about how to apply to current design |
| Reviewing scattered concepts | Quickly locate and consult relevant principles |
| Learning new knowledge | Read unfamiliar principles, deepen with search |
| Diagnosing game problems | Check connections between principles, identify violated principles |
| Solving design problems | Consult "problem-solving methods," combine with relevant principles |

## 4. Pareto Principle: 80/20 Resource Allocation

### Core Principle

20% of core features determine 80% of the player experience quality.

### Execution Steps

1. **Identify core features**: List all features → assess usage frequency and impact → find features that account for 80% of playtime
2. **Resource priority**: Invest main resources in perfecting core features, ensuring high quality and low bug rates
3. **Continuous optimization**: Prioritize fixing core feature bugs, prioritize optimizing core user experience
4. **Periodic evaluation**: Early game stages often repeat the most, invest accordingly; late content may only account for 20% but attract 80% of investment

### Constraints

80/20 is a guiding principle, not an absolute precision value. Secondary features may become differentiating highlights in certain situations.
